### 1.1 补丁铁律
1. 源码改动只在 `deploy\_local\*` 做，**必须提交 `patches` 分支**（`patch: 功能名`，一功能一提交）并 `git push mine patches --force-with-lease`；不留散落改动/stash。
2. 官方克隆（`deploy\ServerS5A3`/`PurpleMagic`）**只 `git pull`**：不建分支、不放改动、不编译、不部署；兼 mirror 备用通道与 `gmindex` 运行时宿主，勿删。
3. 冲突合并：与本地功能重叠的上游改动**手工合并保留本地功能**，其余以上游为准；rebase 前自动打 `patches-pre-rebase-<日期>` tag 可回滚。
4. 误删补丁用 `git checkout patches -- <路径>` 恢复；历史备份 `deploy\_local_patches_backup_*`、归档 `数据迁移\go-server-merge-archive.zip`（仅取所需文件，勿整目录覆盖）。

## 2. 测试（发布前必过）

> **Go 固定 1.26.5（强制）**：本机 `G:\Go`、服务器 `/usr/local/go`、Dockerfile `golang:1.26.5-alpine` 三处一致。发布前 `go version` 校验输出 `go1.26.5`。**禁止 1.27+**：Windows 编译器 SSA 阶段偶发 ICE/段错误（`internal compiler error`、`traceback did not unwind completely`），`go test`/`go build` 随机失败。若已装 1.27，从 `https://mirrors.aliyun.com/golang/go1.26.5.windows-amd64.zip` 下载后**整目录替换** `G:\Go`（不要合并，否则残留 `src/internal/strconv` 等文件导致标准库重复定义）。

```powershell

$NOOPT = '-gcflags=all=-N -l'                     # 关 SSA 优化，绕开编译器崩溃（单个参数）
$env:DNFBRIDGE_REAL_PVF_SMOKE = "F:\90cn\轻装上阵\client\Script.pvf"
# 冒烟（必做）
go test $NOOPT ./internal/services/dnfbridge/ -run "TestRealPVFCeraShopCatalogResolvesAtLeastOneSupportedProduct|TestRealPVFCeraShopMultiBonusMatchesObservedLoveLetterRows|TestRealPVFCeraShopCatalogResolvesObservedCurrentCommodity|TestRealPVFDayDungeonShopAllGoldPriced"
```

## 4. 服务端发布（S5A3）

### 4.1 服务器 docker build（仅首次 / 改 Dockerfile 时兜底）

> 含复杂引号的 python 一律写成 `.sh` 上传执行（PowerShell + ssh 多层引号必炸）。

```bash
# ① 清残留（见 §3）
# ② 构建镜像（只跑 docker build 一步；内存上限防 OOM）
cd /srv/apps/ServerS5A3
export GOPROXY=https://goproxy.cn,direct
docker build --memory=4g --memory-swap=6g -t servers5a3-local:dev -f deploy/docker/Dockerfile .
docker tag servers5a3-local:dev servers5a3-local:pre<日期>   # 回滚保险（覆盖 dev 前）
# ③ up：server_ip 临时改私网（check_network 要求），显式选 120 频道基线
cd runtime/docker && sed -i s/124.221.247.221/10.253.90.2/ instance.json
cd /srv/apps/ServerS5A3
python3.12 deploy/docker/manage.py up --host-ip 10.0.0.14 --channel-info go-server/internal/services/dnfbridge/testdata/channel_info.etc
```
> **勿跑 `build.sh`**：Dockerfile 已编译好二进制，宿主机再编译一轮会打满 4C/7G 致 SSH 无响应。

**up 后 post-fix（必做，写成 .sh 执行）**：
```bash
cd /srv/apps/ServerS5A3/runtime/docker
sed -i 's/^DNFBRIDGE_SERVER_IP=.*/DNFBRIDGE_SERVER_IP=124.221.247.221/' server.env
sed -i 's/"server_ip": "10.253.90.2"/"server_ip": "124.221.247.221"/' instance.json
python3 -c "import json; P='compose.json'; d=json.load(open(P)); d['services']['db'].setdefault('ports',['127.0.0.1:3307:3306']); json.dump(d,open(P,'w'),indent=1)"
# 写回 admin secret（up 从 instance.json 重建 env 会清空；不清则 admin API 全 404）
python3 - <<'PY'
import json
g = json.load(open('/srv/apps/PurpleMagic/runtime/selfhost/gateway.json', encoding='utf-8'))
token = g['management']['gameToken']; p = 'server.env'
out, found = [], False
for line in open(p, encoding='utf-8').read().splitlines():
    if line.startswith('DNFBRIDGE_PLAYER_ADMIN_SECRET='):
        out.append('DNFBRIDGE_PLAYER_ADMIN_SECRET=' + token); found = True
    else: out.append(line)
if not found: out.append('DNFBRIDGE_PLAYER_ADMIN_SECRET=' + token)
open(p, 'w', encoding='utf-8').write('\n'.join(out) + '\n')
PY
docker compose -p servers5a3-local -f compose.json up -d --force-recreate server
docker inspect servers5a3-local-server-1 --format '{{.State.StartedAt}}'
```
- 三条作用：SERVER_IP 回公网、补 db 3307 映射（每次 up 都丢）、补 admin secret（每次 up 都清）、`--force-recreate` 让 env 生效（`restart` 不重读）。`-p servers5a3-local` 不能省。
- 频道表 120 基线：up/prepare 校验摘要，不符即拒。旧表先 `sha256sum` 留档再 **`mv` 出 `data/` 目录**（同目录改 `.bak` 不算）；基线 sha `5630b099…`，CSV 不行。
- **假成功自查**：`StartedAt` 必须晚于发布时间；日志 `dnfbridge started` 时间要新；含 `game_ports=120`、`server_ip=124.221.247.221`。

### 4.2 本地编译 + 持久化目录（日常首选，服务器零编译）

服务器 4C/7G，在服务器上编译曾打满 CPU 致 SSH 无响应、被误判死机强制重启（db 崩溃恢复）。**本地交叉编译 → 上传持久化目录 → 只重建 server 容器**：服务器不编译、不动 db/gateway/频道表，30 秒完成、秒级回滚。

**一次性前提（已完成，勿重复）**：
- `runtime/docker/compose.json` 的 server 服务已加 `"entrypoint": ["/runtime/DNF90Server"]`。
- 持久化目录 `runtime/docker/server/`（挂载到容器 `/runtime`，rw）已放二进制；容器 `user:"0:0"`、`/runtime` 可写。
- **不要再跑 `manage.py up`**（会用旧模板重生 compose.json 抹掉 entrypoint）；§4.1 post-fix 改 db ports 的 python 是整读写 json，会保留 entrypoint。若误跑 up 丢了 entrypoint，重新 `python3 -c` 写回即可（镜像内 `/usr/local/bin/DNF90Server` 始终是最初旧版、不会自动生效，不会误用）。

## 8. EXE 换版（**免重建登录器**，一条命令）

**改 `DNF.exe` 不需要重建登录器、不需要发新 bundle、不需要改内嵌 `launcher-input/profile.json`。**

原理：登录器是否要求更新只看 `MinimumLauncherVersion` 与 `SupportsProfile`，二者不随 EXE 变。校验 EXE 的三处指纹全部来自网关签名下发：本地 `profile.ExeSha256`、下载清单 `content.files["DNF.exe"]`、双开白名单 `profile.SecondClient.SupportedHashes`。新 EXE 只需重签 content + 改网关下发 profile，玩家在线拉到新 bootstrap 自动追平。

```powershell
# 一步完成：重签 content manifest → 上传新 EXE blob + manifest → 停网关 → 双改 profile/state
#           (ExeSha256 + SecondClient.SupportedHashes + sequence+1) → 起网关 → publish
cd F:\90cn\轻装上阵
python deploy\tools\release\release_exe.py
#   --dry-run 只本地重签不上传；--version x.y.z 指定 content 版本(默认末位+1)
```
**验证（缺一不可）**：
```powershell
python F:\90cn\轻装上阵\deploy\tools\release\verify_bootstrap.py 124.221.247.221 8443
# MATCH(profile==content): True ｜ blob Range: 206 ｜ sequence 已 +1 ｜ AntiCheat 仍在
#   launcher 版本保持原值（不再因 EXE 换版递增），不是校验失败
```
- `release_exe.py` 已内置：两处 profile(`player-profile.json` + `state.json`) 同时改 ExeSha256 与 SupportedHashes、sequence+1；**漏改 state 会导致网关 `launcher Hub configuration invalid` 重启循环**，勿手工只改一处。
- 改 state/profile **必须先停网关**（工具已处理）；运行中网关管理请求会把内存旧 profile 写回覆盖。
- `SecondClient` 缺省/空列表 = fail-closed 拒绝双开；换版务必含新 sha（工具自动追加）。AntiCheat 段保持 audit，勿删。
- content manifest 的 `Length` 必须等于新文件字节数（工具自动取）；白名单外路径静默过滤。

### A.1 多买多送（自改核心已舍弃，循环模式 patch 上线）
旧本地自改核心已舍弃（`14de9b8b`），`festival.go`/`cera_shop_purchase.go`/`private_festival.go` 回退官方 base；官方已内置多买多送。`3e4a0fe0` 增加循环结算：`festival.Period.Cycle()` 识别 PVF `RepeatFrom>1 / RepeatItem=0 / RepeatCount=0` 为循环模式，`Apply` 对第 N≥RepeatFrom 套映射回模板档位重发（邮件 `CompletionKey` 去重），wire 隐藏循环标记避免 ×0 空卡。改周期只需改 PVF `RepeatFrom`（周期=RepeatFrom-1），服务端无需再动。配套 PVF + content 已上线。回滚：git revert `3e4a0fe0` + 换回 PVF + seq+1。

### A.2 动态深渊/裂缝掉率 + 保底件数档（GM 面板）
- **掉率**：游戏服 `nativeHellRateOverride`/`riftEpicRateOverride`（atomic，-1=PVF）+ admin action `get/set_hell_drop_rate`/`get/set_rift_drop_rate` + 网关 `/api/v1/*-drop-rate` + GM 前端。掉率 0..1000‰，-1 恢复 PVF。当前 PVF 基线：普通深渊 19‰、裂缝 1000‰。
- **件数档**：`hellPieceCountOverride`/`riftPieceCountOverride`，三模式 `pvf`/`rate`/`count`(1–N)，另有 `off`(0)。与概率档双向互斥。普通深渊在 `currentFixedCountHellReward()`、裂缝在 `selectItems()` 用私有 RNG 抽目标件数 T 只发 T 件（不污染主序列）。协议 `hellDropCount`/`riftDropCount`，网关 `POST /api/v1/*-drop-count`。

- 回滚：面板 `-1` 回 PVF，或 git revert 对应 patch 重发。
